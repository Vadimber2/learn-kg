# Аудирование (STT): слушай — повтори — получи балл

Раздел эксперимента: ученик слушает эталон, повторяет вслух, запись уходит в
ElevenLabs Scribe, ответ сверяется пословно и превращается в балл. Тот же
механизм даёт кнопку «Говорить» на карточках.

Код: `app/src/render/028-renderListen.js` (рендер + чистые функции),
данные — `app/src/data/stt-blocks.js`, сервер — ручка `POST /api/stt/<mod>`
и учёт в `/data/stt-usage.json`. Гейты — `tests/stt.test.js`.

## Правила, которые нельзя нарушать

1. **Запись MUST открываться только после прослушивания эталона** — это и есть
   протокол имитации; «повтори, не услышав» ломает измерение.
2. **Каждое значимое действие MUST слать `evPush("stt.result", …)`** — событие
   идёт в журнал занятий, ленту учителя и «Мой прогресс». Раздел без трекинга
   не считается готовым (правило владельца).
3. **Механика — по науке, а не «на глаз»**; источники записаны прямо в коде
   рядом с очередью (elicited imitation — Yan et al. 2016, мета-анализ r=0.66;
   shadowing — Hamada 2016; retrieval practice). Меняешь порядок или протокол —
   меняй вместе с обоснованием.
4. **Набор дня стабилен внутри дня** (лимит дневной — и очередь дневная):
   порядок задаёт `sttQueue` с сидом от даты, приоритет — фразам с подошедшим
   SRS-сроком, дальше от коротких к длинным.
5. **Новый блок = запись в реестре, ноль правок логики**: `STT_BLOCKS` +
   титул `stt_b_<id>` в словарях трёх языков. Рендерер `kind:"sounds"` общий и
   про конкретные звуки ничего не знает.
6. **Платная опция считается**: каждый вызов пишется в `/data/stt-usage.json`
   (записи, секунды, символы) и виден преподавателю в карточке ученика.
   Раздел без учёта затрат не готов.
7. Кнопка на карточке живёт **только на шаге «узнавание»** и только у слова с
   озвучкой: на шаге ввода подсветка эталона показала бы ответ.

## Порядок добавления блока

```
Блок <id>:
- [ ] 1. Запись в STT_BLOCKS (kind sounds + items), «фразы дня» остаются первыми
- [ ] 2. Титул stt_b_<id> в трёх словарях
- [ ] 3. Описания d/dEn/dTr: >20 знаков, ориентир из своего языка, hint при m2
- [ ] 4. npm test (stt.test) зелёный
```

## Что где

| Тема | Где | Деталь |
|---|---|---|
| Реестр блоков | `app/src/data/stt-blocks.js` | `kind:"queue"` — фразы дня; `kind:"sounds"` — дрилл со своим `items` |
| Гласные | `STT_VOWELS` там же | `ch`, `m`/`m2` (долгая пара), `hint`, описания `d`/`dEn`/`dTr` |
| Очередь и пул | `sttQueue`, `sttPool`, `sttVowelWords` | чистые функции — тестируются в vm |
| Балл | `sttScoreText` | «Совпадение: N% · лучший: M%» (лучший показывается, только если выше) |
| Кнопка на карточке | `sttCardBtn` (12-app.js) | общий транспорт `sttSend` |
| Доступ и лимит | `students.json`: `stt`, `sttLimit` | дефолт 20/день, допустимо 1..500; преподавателю безлимит |
| Учёт | `/data/stt-usage.json` | секунды берутся из таймингов слов ответа |

Подробности механики, доступа и как заводить новый блок —
`references/mechanics.md`.

## Ограничения на сегодня (осознанные)

- Вкладка показывается **только у m0** (`id==="m0"` в 12-app.js) и не входит в
  `STUDY_TABS`. Блоки для M1+ уже поддержаны реестром — при их появлении нужно
  снять это ограничение осознанно, а не «заодно».
- Опция недоступна ученику без единого постоянного курса (чисто триальному);
  в демо реестр едет целиком как справочный материал, но вкладки нет.
- Описания звуков пересказывают урок произношения и подчиняются канону
  «ориентир берётся из языка дорожки» (в русском описании — русские опоры,
  в английском — английские).

## Реестр блоков: полный формат записи (перенесено из CLAUDE.md 22.08.2026)

`STT_BLOCKS` в `app/src/data/stt-blocks.js`. Обязательное: `id`, `kind`
(`queue` — фразы дня, `sounds` — дрилл со своим `items`), титул `stt_b_<id>`
в трёх словарях. Наборы дриллов: гласные `STT_VOWELS`, согласные
`STT_CONSONANTS`, окончания сказуемости M1 `STT_ENDINGS`.

Необязательные поля записи:

| поле | смысл |
|---|---|
| `mods` | модули, где блок показан (нет поля = везде) |
| `intro` / `words` | свои ключи подписей вместо звуковых |
| `track` | тема урока модуля, где утверждение подтверждено источниками (гейт сверяет существование, UI даёт ссылку) |

Поля item: `ch` (подпись чипа), `m` / `m2` (подстроки поиска фраз; второй набор —
долгая пара или вежливая/оглушённая форма) с `hint`, `label`, `not` (точные
фразы-исключения), `snd` / `snd2` — дорожки самого звука буквы (краткий и долгий),
их ученик слушает отдельно от слов.

**Вкладка открыта модулям из реестра `STT_MODS`** (m0 — звуки, m1 — окончания):
следующий модуль = строка списка, но только вместе со своим материалом.
Реестр целиком едет в демо-срез (справочный материал), вкладки в демо нет.

**Дорожки звуков заводятся в `PHONETICS`** (`deploy/gen-audio.js`) текстом-повтором:
«А, а, а.», согласные — слогами («Жа, жо, жу.»), ң только с гласной впереди.
Причина: одиночная буква — сверхкороткое тело, на нём v3 отдаёт пустой ответ и
сервер уходит на модель без кыргызского. Ссылка на дорожку без цели в m0 валит
`gen-audio.test`; нет файла — кнопки просто нет (молчащих кнопок не бывает).

Хоткеи (`sttHotkey`, физические коды клавиш): Пробел — говорить,
модификатор+Пробел — слушать, → — дальше.

Учёт затрат — `/data/stt-usage.json` (записи, секунды, символы), виден
преподавателю в карточке ученика. Внешний вызов в тестах мокается
`env ELEVEN_STT_URL` — реальный ключ тестам не нужен.

Скоринг на карточках: `sttCardBtn` — только на шаге «узнавание» (на вводе
подсветка эталона выдала бы ответ) и только у слова с озвучкой; тот же лимит и
журнал через общее ядро `sttSend` (маркер `===STT===`), балл строкой
`sttScoreText` («Совпадение: N% · лучший: M%») в обоих местах.
