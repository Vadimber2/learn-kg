# Оценки скиллов: как прогонять

Формат `skill-evals.json` — по документации Anthropic (`skills` / `query` /
`expected_behavior`). Встроенного раннера у Anthropic нет: *«There is not
currently a built-in way to run these evaluations»*, поэтому прогон делается
субагентами.

## Процедура

1. **Прогон со скиллом.** На каждый сценарий — по субагенту на модель
   (Haiku, Sonnet, Opus): документация требует тестировать всеми моделями,
   с которыми скилл будет использоваться. Промпт субагента:
   «Прочитай `.claude/skills/<name>/SKILL.md` и нужные references. Задача:
   `<query>`. Ответь нумерованным планом: файлы, реестры, требования, гейты.
   Ничего не меняй в репозитории.»
2. **Baseline.** Тот же запрос **без** скилла (запретить читать
   `.claude/skills/`) — чтобы видеть, что даёт именно скилл, а не общая
   сообразительность модели.
3. **Оценка.** Считается доля пунктов `expected_behavior`, которые агент
   назвал сам. Пункт засчитывается, только если названо конкретное место
   (файл/реестр), а не общая формулировка.
4. **Итог** заносится в `results-<дата>.md` рядом: покрытие по моделям,
   что пропустили все модели (это дефект скилла, а не модели), что нашлось
   только со скиллом.

## Как читать результат

- **Пункт пропущен на всех трёх моделях** → чинить скилл: правило
  недостаточно заметно или отсутствует.
- **Пропущен только на Haiku** → правило есть, но требует больше явности
  (документация: «What works perfectly for Opus might need more detail for Haiku»).
- **Baseline нашёл сам** → пункт можно сократить, он не добавляет знания.

## Грабля стенда: установленная копия ломает замер

`run_loop.py` кладёт **временную копию** скилла (`<имя>-skill-<хеш>`) и считает
срабатыванием только вызов этой копии. Если настоящий скилл уже установлен
(в проекте или глобально), модель вызовет **его**, а стенд запишет «не
сработало» — мы получили 0 из 9 на положительных запросах при полностью
исправном скилле.

Поэтому перед прогоном инструментом временно убери установленные копии
(проектную и глобальную) либо мерь напрямую:

```bash
env -u CLAUDECODE claude -p "<запрос>" --output-format stream-json --verbose \
  --include-partial-messages --model sonnet 2>/dev/null | grep -o '"skill":"[a-z0-9-]*"' | head -1
```
Вывод — имя реально выбранного скилла (или пусто). Так проверяется и попадание,
и разграничение: правильный ли скилл выбран из нескольких похожих.

Инструмент так же оставляет временные копии в `~/.claude/skills` и файлы команд
в проекте — после прогона убедись, что мусора не осталось.

## Форк против явной модели

Субагент типа `fork` наследует модель родителя, поэтому для сравнения моделей
он не годится — нужен обычный субагент с явным переопределением модели.
Форк удобен для baseline в том же контексте.
