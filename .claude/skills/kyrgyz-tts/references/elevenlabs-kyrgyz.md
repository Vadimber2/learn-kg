# ElevenLabs для кыргызского — API и проектная интеграция (learn.kg)

## Факты о поддержке кыргызского (проверено 2026-08)

- Кыргызский поддерживает **только `eleven_v3`** (в доке — Kirghiz/kir; в API работает ISO-код `ky`).
- `eleven_multilingual_v2`, `eleven_flash_v2_5`, `eleven_turbo_v2_5` кыргызского НЕ знают —
  серверный фолбэк на multilingual_v2 (короткие слова) даёт не-кыргызскую фонетику.
- Клонирование: IVC работает (клон «KG Voice» сделан из 3×60 с чистой записи, фрагменты
  отбирались по метрикам: без клиппинга, речь −23…−18 dB RMS, фон ≤ −60 dB).
- **Отбор фрагментов для IVC — что действительно можно измерить**: длительность, пик и
  клиппинг, RMS речи, уровень самого тихого окна (шум комнаты). Уровень нормализуется
  усилением до −21 dBFS RMS с гарантией пика ≤ −3 dBFS.
  **Чего измерить НЕЛЬЗЯ** (проверено на своей шкуре): «музыка это или речь» —
  спектральная плоскость, поиск ритма по огибающей и стабильность F0 все три провалили
  кросс-проверку на заведомо речевой записи (дали «музыкальные» показатели и медиану F0
  174 Гц у мужского голоса). Не выдавать такие оценки за факт: спрашивать владельца.
  Разный тональный баланс записей (у одной 68% энергии в 100–300 Гц, у другой 81% в
  300–3400 Гц) объясняется микрофоном/срезом низов, а не наличием подложки.
  PVC для кыргызского недоступен: сэмплы принимаются только на языках Flash/Turbo,
  и PVC «not yet optimized for v3».

## Прямой запрос к API (пилоты, эксперименты)

```
POST https://api.elevenlabs.io/v1/text-to-speech/<VOICE_ID>?output_format=mp3_44100_128
headers: xi-api-key: <KEY>, Content-Type: application/json
body: { "text": "…", "model_id": "eleven_v3", "language_code": "ky",
        "voice_settings": { "stability": 0.5|1.0, "similarity_boost": 0.75 } }
```

- stability в v3 — строго 0 / 0.5 / 1.0 (Creative/Natural/Robust). Creative не использовать.
- Прод отдаёт `mp3_44100_192` (`ELEVEN_FORMAT` сервера); для проб хватает 128.
- Пустое тело при HTTP 200 — известный сбой v3 на сверхкоротких текстах: ретраить, НЕ фолбэчить
  на v2 при работе напрямую.
- Аудио-теги (`[whispers]` и т.п.) — не для учебной озвучки.
- Лимит 5000 символов/запрос; кредиты = символы; остаток: `GET /v1/user/subscription`.
- Скоуп API-ключа для генерации: TTS Access + Voices Read + User Access, остальное No Access,
  на ключе — credit limit.

## Контроль произношения — что работает в v3

| Способ | v3 | Как |
|---|---|---|
| IPA в тексте | да | `/фонемы/` слэшами, ТОЛЬКО внутри обычного предложения: `Бул — /yj/.` |
| Голый IPA всем текстом | НЕТ | читается как тарабарщина — запрещено |
| SSML `<phoneme>` | НЕТ | только flash/turbo v2 |
| Словари `.PLS` (`ELEVEN_DICT_ID`) | НЕТ | полноценно только v2/v2.5 |
| Орфоэпическая перезапись | да | текст запроса «как слышится» (правила — kyrgyz-phonetics.md) |
| Перегенерация той же фразы | да | v3 недетерминирован — часто хватает второй попытки |

## Контроль качества сгенерированного (замеры на 150 файлах m0, 2026-08)

- **Темп живой речи клона**: медиана 14.5 знаков/сек, p10 9.0, p90 18.0, максимум 23.6.
  Отсюда порог грубого обрыва в `gen-audio.js` — 26 знаков/сек (выше живой речи).
- **Обрыв хвоста** — главный дефект v3 (≈4%: 6 явных + 12 пограничных из 150).
  Детектор: энергия последних 80 мс / энергия всего файла (`deploy/audit-audio.js`,
  функция `tailRatio`): >0.5 обрыв, 0.3–0.5 подозрительно, <0.3 норма. Нормальная фраза
  кончается тишиной, обрезанная — на полной громкости. Темп для коротких слов бесполезен.
- **Лечение** (эмпирика): 1–2 перегенерации в Natural снимают 17 из 18 случаев;
  упорный («Ийгилик каалайм!», 4 неудачных дубля) вылечен stability 1.0 Robust с первой попытки.
  Поэтому `gen-audio.js` с третьей попытки сам переходит на Robust, а `audit-audio.js --fix`
  повторяет ту же эскалацию.
- Аудит: `KGA1_AUTH=… KGA1_BASE=https://learn.kg [KGA1_ONLY=…] [KGA1_FIX=1 KGA1_VOICE=…]
  node deploy/audit-audio.js m0` — декодирует через системный `afconvert` (macOS),
  upload/sfx не проверяет и не правит.
- **Вердикт «звучит не так» сначала проверяй на обрыв**: усечённый файл маскируется под
  плохое произношение и портит сравнение вариантов текста.
- **Выброшенное целое слово — слепая зона ВСЕХ автодетекторов** (кейс «сагынасызбы»,
  m12): модель опустила последнее слово и растянула оставшиеся — хвост затухает чисто
  (0.02), темп 6.4 сл/с в норме. Ловится только ухом или STT-сверкой (Scribe; нужен скоуп
  Speech to Text на ключе). Лечение: дубли с гейтом по длительности (слоги/5.6…слоги/3.1 с)
  и чистым хвостом, генерить ЛОКАЛЬНО и заливать PUT только годный дубль — он получает
  source:"upload" и этим защищён от перезаписи будущими прогонами (осознанный трюк:
  проверенный вручную дубль приравнен к записи преподавателя).
- **Съеденный последний согласный** — отдельный дефект, детектором затухания НЕ ловится
  (носовой [м] тихий, файл «нормально» кончается тишиной). Признак: длительность речи
  заметно короче, чем у того же текста в Robust. Пример: «Атыңыз ким?» Natural 0.66 с
  без [м] → Robust 0.86 с с [м] (+30%). Отсюда правило `stabilityFor`: карточки-слова
  генерируются в Robust, связная речь реплик и куплетов — в Natural.
- **Слоговой темп как sanity-check**: считать слоги по гласным ядрам (долгие пары
  аа/оо/ээ/өө/уу/үү склеивать в ИСХОДНОМ тексте, иначе «са-лам» схлопнется в один слог).
  Замер по 150 файлам m0: медиана 4.8 слога/сек, p10 3.3, p90 6.4, максимум 7.4.
  Это в пределах естественной речи по литературе (2–8 сл/с; Coupé et al. 2019, Science
  Advances — 17 языков; Pellegrino et al. 2011 — испанский 7.82, английский 6.19,
  мандарин 5.18), поэтому «нефизично» начинается не с 8, а примерно с 9–10 сл/с:
  порог физиологии выше, чем нормальная речь. Ниже 9 темп ничего не доказывает.

## Проектный пайплайн kyrgyz-a1

- Серверная ручка: `POST /api/tts/<mod>` (teacher/admin; body `{id, text, force?, voice?, model?, lang?, settings?}`).
  Текст режется до 500 символов. `voice` явный отключает автофолбэк «первый голос аккаунта».
  При `source:"upload"` без `force` — 409.
- Файлы: `/data/audio/<mod>/<id>.mp3`, мета `_meta.json` (`{source, by, at, voice}`); id — `^[a-z0-9_]{1,40}$`.
- Бакет m0: всё с префиксом `ph_` (реплики диалогов, куплеты, фонетика) живёт в
  `/data/audio/m0/` — клиент ищет через `homeOf()`. Реплику модуля mN генерировать в бакет mN — ошибка.
- Батч: `KGA1_AUTH=логин:пароль KGA1_VOICE=<voice_id> [FORCE=1] node deploy/gen-audio.js m0 m1 …`
  Прогон m0 кроет и все диалоги/куплеты. FORCE перегенерирует только source:"tts" и записи без
  меты; upload (записи преподавателя, песни Suno) и sfx (амбиенты) не трогаются никогда.
  После модуля скрипт сверяет `_meta.voice` с ожидаемым и печатает непокрытые цели.
- Смена голоса курса: env `ELEVEN_VOICE_ID` в Coolify → удалить файл-оверрайд `/data/tts-voice`
  (он сильнее env!) → рестарт → `GET /api/tts/health` показывает voice/model.
- Демо-ловушка: при старте процесса ВСЕ `ph_*.mp3` из m0 попадают в публичный анонимный
  демо-снимок. Временные дорожки (`ph_pilot_*`) удалять `DELETE /api/audio/m0/<id>.mp3`
  до ближайшего рестарта/деплоя.
- Прослушивание с прода требует логина (анониму — 401): вычитчик входит на https://learn.kg
  своим аккаунтом, потом открывает `https://learn.kg/api/audio/m0/<id>.mp3`.
- Ключи и voice_id — `deploy/CREDENTIALS.md`, раздел «ElevenLabs (озвучка фраз)».

## Порядок массовой перегенерации (по плану)

1. Пилот одобрен нейтив-спикером (короткие слова, фразы, реплики; выбор stability).
2. `ELEVEN_VOICE_ID` переключён, health-check зелёный.
3. `FORCE=1 gen-audio.js m0` (самый большой и видимый бакет) → рестарт (демо-снимок) → m1…m23 пачками.
4. По логам собрать фразы, ушедшие через фолбэк-модель — точечная переслушка.
5. Переслушку начинать с диалогов/куплетов (без гейта audioOk), карточки — выборочно;
   брак лечить по эскалации из SKILL.md, п. 5.
