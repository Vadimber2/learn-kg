# Новый модуль: чеклист с точными местами и гейтами

Скопируй этот список в ответ и отмечай по мере выполнения:

```
Модуль m<n>:
- [ ] 1. Данные m<n>.js (CATS/VOCAB/DRILL)
- [ ] 2. content/m<n>.js — запись в CONTENT + catsEn/catsTr/drillGroups/plan
- [ ] 3. dialogs/m<n>.js (если есть) + запятая в предыдущем фрагменте
- [ ] 4. CONTENT_READY + эталон в tests/content.test.js
- [ ] 5. MODULE_META + титулы EN/TR
- [ ] 6. MODULE_EXTRAS + рендерер + строка в manifest.json
- [ ] 7. COURSES.<курс>.modules
- [ ] 8. REVISION_MODS / B1_MODS / конкатенация M<n>_REFS (если применимо)
- [ ] 9. Пороги данных пройдены (npm test зелёный, число сьютов сверено)
- [ ] 10. Озвучка + аудит затухания = 0
```

Столбец «поймает» — что упадёт, если шаг пропустить. Где написано «молча» —
гейта нет, проверяй сам.

| # | Что | Где | Поймает |
|---|-----|-----|---------|
| 1 | `CATS_M<n>`, `VOCAB_M<n>`, `DRILL_M<n>` | `app/src/data/m<n>.js` | content.test (пороги), server.test (реестры) |

| 3 | Диалоги (опционально — их нет у m10/m11) | `app/src/data/dialogs/m<n>.js` | забытый файл **не ловится ничем** — модуль просто без диалогов |

| 5 | `CONTENT_READY` | `app/src/data/content.ready.js` | content.test: сверка с эталоном |

| 9 | Рендерер `NNN-render<Grammar\|Ref>M<n>.js` | `app/src/render/` | **старт сервера**: тело функции вырезается регекспом для демо-сборки |

| 11 | Модуль в `COURSES.<курс>.modules` | `server/server.js` | старт: «COURSES и app/src разошлись по модулям» |

**Инвариант порядка (ловушка).** Сверка идёт **строкой**: `COURSE_IDS.flatMap(…)`
против `appshell.MODULES`, а последний отсортирован **по числу** в имени файла.
Значит id модулей обязаны идти возрастающими блоками по курсам: дописать `m36`
в середину (например, в конец A2, когда B1 уже занял m24–m35) — мгновенный
`throw` при старте, потому что порядок разойдётся. Новый id всегда продолжает
нумерацию за последним модулем последнего курса.
| 12 | Эталон `CONTENT_READY` **руками** | `tests/content.test.js` | content.test — осознанная подпись «готов» |
| 13 | Повторительный **и экзаменационный** модуль — в `REVISION_MODS` | `tests/content.test.js` | content.test: иначе падают на пороге ≥85 |
| 14 | Для B1+: модуль в `B1_MODS` | `tests/b1.test.js` | иначе модуль молча вне гейтов уровня |
| 15 | Для B1+: `M<n>_REFS` в конкатенацию массивов | `tests/b1.test.js` (строка с `M24_REFS.concat(…)`) | **молча**: пруфы нового модуля просто не проверяются |
| 16 | Новый персонаж диалога | `deploy/voices.json` | b1.test (персонажи в реестре голосов) — падает на `npm test`, до озвучки |

**Контракт имени рендерера жёстче, чем кажется**: мало положить файл с нужным
именем — функция обязана иметь ровно сигнатуру `(m)` и закрывающую `}` в начале
строки. Демо-сборка вырезает тела платных рендереров регекспом по манифесту и
роняет старт словами «не найдены тела … — вырезать платный контент нечем».

## Пороги данных (самые частые красные)

- **≥85 своих (не-alias) единиц**; исключения вверх — `RAISED` (`m0`–`m3`: 90).
  Модули из `REVISION_MODS` — ровно 0 своих.
- **Дриллов ≥10**, у каждого **ровно 4 варианта** и `c` в диапазоне 0–3.
- **`drillGroups` ≥2**, у каждой `name`/`rule`/`nameEn`/`ruleEn` и хотя бы одно
  задание; каждый дрилл привязан к существующей группе.
- **Перекос правильных ответов по позициям ≤50%** — иначе ученик угадывает.
- `drillLabel` и `refLabel` у модуля обязательны; `en`-глосс — у каждой фразы;
  `catsEn`/`catsTr` — **обязательны** (ключи сверяются с `cats`).
- `kgw("текст","id")` в рендерах обязан совпадать побуквенно с `ky` карточки.
- Alias `{ref:"m<k>_<nn>"}`: формат строгий, донор из **более раннего** модуля
  по `CONTENT_READY`, alias на свой модуль и alias-на-alias запрещены, дубль
  ky-фразы между модулями запрещён.

## B1 и выше — что реально проверяет `tests/b1.test.js`

- Пруфы: `≥3` тем считается по **объединению** всех `M<n>_REFS` уровня, а не по
  каждому модулю; у каждого пруфа — `tema`, `subtest` и URL на
  сайт официального тестирования — ПРАВИЛО ОТМЕНЕНО 30.10.2026 (CLAUDE.md «Экзамен курса»): пруфов-ссылок туда больше нет; дисциплина «3–6 пруфов на модуль» держится вручную;
  повторительный и экзаменационный модули REFS не имеют.
- Соответствие титула теме проверяется **только для m24** (там ловили «Детство»
  на модуле про учреждение) — для остальных это дисциплина, не гейт.
- Каждый дрилл: `qKy` (кириллицей, >5 знаков) + `q`/`qEn`/`qTr`.
- Каждое своё слово: `def` (>10 знаков); незнакомых токенов ≤20%, каждый —
  в `DEF_GLOSS_M<n>` с ru/en/tr; последняя строка данных модуля —
  `DEF_GLOSS.m<n>=DEF_GLOSS_M<n>;` (сам реестр объявлен в `app/src/data/b1.head.js`).
- ≥85 своих единиц проверяется здесь повторно.

## Озвучка модуля

```bash
KGA1_AUTH="…" KGA1_VOICE=<voice_id> node deploy/gen-audio.js m<n>
KGA1_AUTH="…" node deploy/audit-audio.js m<n>        # до 0 подозрительных
```
Реплики диалогов и куплеты **всех** модулей живут в бакете `m0` (`ph_*`) и
генерируются только прогоном `m0`. `FORCE=1` не трогает `upload` и `sfx`.
Караоке: `kt` у куплетов, `skt` у полной песни — гейт «≥70% строк прямого
матча» относится только к `skt` (песня без него просто не подсвечивается).
Автоматической проверки «аудит = 0» в `npm test` нет — это дисциплина выпуска.

## Проверка перед PR

```bash
npm test 2>&1 | grep -c ': OK'      # сверить с числом сьютов из CLAUDE.md
docker build -q -t kga1 . && docker run --rm -v "$PWD":/src:ro node:22.23.4-alpine@sha256:fe4f6d74e20370acb04ad889077d14d0f64a9c8ea6a42bc60cddf1e844699914 \
  sh -c 'cp -r /src /app && cd /app && npm test 2>&1 | grep -c ": OK"'
```
Канон тестирования: механизм, параметризованный набором, проверяется
**перебором** (одиночные модули, пары, набор без первого) — дефекты замыкания
доноров и тропы в «типовом» наборе невидимы. Набор кейсов сборки живёт в
`tests/appshell.test.js` и перечислен руками — новый уровень требует своих строк.
